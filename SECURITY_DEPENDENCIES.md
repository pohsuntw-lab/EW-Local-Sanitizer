No cloud client, telemetry package or runtime web service is included. The Electron shell and its archive extractor contain documented native executables needed for the approved desktop UI/install boundary; the scanning core and OCR remain local TypeScript/WASM. Tests compile with `tsc` and run emitted JavaScript, so they do not depend on Node's direct TypeScript execution behavior.

`pdfjs-dist` records optional `@napi-rs/canvas` packages in the lock graph, but installation uses `--omit=optional` and the application does not import or execute them. The lock therefore mentions `@napi-rs/canvas` 1.0.9 and the MIT platform packages `@napi-rs/canvas-android-arm64`, `@napi-rs/canvas-darwin-arm64`, `@napi-rs/canvas-darwin-x64`, `@napi-rs/canvas-linux-arm-gnueabihf`, `@napi-rs/canvas-linux-arm64-gnu`, `@napi-rs/canvas-linux-arm64-musl`, `@napi-rs/canvas-linux-riscv64-gnu`, `@napi-rs/canvas-linux-x64-gnu`, `@napi-rs/canvas-linux-x64-musl`, `@napi-rs/canvas-win32-arm64-msvc` and `@napi-rs/canvas-win32-x64-msvc`; all are optional, uninstalled and outside the text-only PDF path. A later PDF rasterization decision must re-review this native boundary.

Electron's install/development graph is isolated from core scanning. Locked packages are `@electron/get` 5.1.0, `@electron-internal/extract-zip` 1.0.5, `debug` 4.4.3, `ms` 2.1.3, `env-paths` 3.0.0, `graceful-fs` 4.2.11, `progress` 2.0.3, `semver` 7.8.5, `sumchecker` 3.0.1 and optional `undici` 7.29.1. The nested type-only packages are `electron/node_modules/@types/node` 24.13.4 and `electron/node_modules/undici-types` 7.18.2. `@electron/get` and `undici` may access the network only when acquiring the development Electron binary; application source never imports them and network-denied core/UI-session tests do not need them. `@electron-internal/extract-zip` ships prebuilt extraction addons for Electron installation; it is not reachable through renderer IPC or the sanitization workflow.

Electron Builder adds a development-only packaging graph. The lockfile is the complete version/license/integrity inventory for that graph, and the dependency-policy check validates every entry even though each transitive package is not repeated in this narrative document. Network-capable build packages such as `@electron/get`, `got`, `electron-publish` and `simple-update-notifier` are not application dependencies: publishing is disabled, the update notifier is disabled, and artifact inspection must prove that builder/publisher modules are absent from the packaged ASAR. First-time cross-platform packaging may download the pinned Electron Windows runtime and NSIS toolchain into the build cache; this is a build-time action only.

Known build-only debt: Electron Builder 26.15.3 transitively includes Squirrel tooling that is not selected by this project. That unused branch contains deprecated `glob` 7.2.3, `inflight` 1.0.6 and `rimraf` 2.6.3, plus `electron-winstaller` 5.4.0 with a lifecycle script. Installation is performed with lifecycle scripts disabled, the project targets NSIS and portable only, and the dependency check permits only the exact `node_modules/electron-winstaller` 5.4.0 flag as a documented exception. Any version/path change fails closed and requires a new review. `npm audit` currently reports zero known vulnerabilities, but deprecation is still treated as maintenance risk.

The Windows smoke workflow uses official `actions/checkout` v7.0.1 and `actions/setup-node` v7.0.0 pinned to their complete release commit SHAs, grants only read access to repository contents, disables persisted Git credentials and installs the lockfile with lifecycle scripts disabled. It does not use an artifact-upload or release action. The Windows runner is permitted to download build dependencies, but no application document enters CI and no generated EXE leaves the ephemeral job.

Runtime transitives pinned by the lockfile are `fast-deep-equal` 3.1.3 (MIT), `fast-uri` 3.1.7 (BSD-3-Clause), `json-schema-traverse` 1.0.0 (MIT) and `require-from-string` 2.0.2 (MIT). Development transitive `undici-types` 6.21.0 is MIT and contains types only. A full `npm audit` reported zero known vulnerabilities when this baseline was created.

`npm run check:dependencies`, also included in `npm run lint`, runs without network access and rejects non-exact direct versions, manifest/lock mismatch, missing SHA-512 integrity or license metadata, undocumented direct packages, and all lifecycle/native-build flags except the exact documented build-only exception above. The installed dependency tree is also checked for native addon files and runtime network-module references. A fresh full `npm audit` on 2026-09-11 reported zero known vulnerabilities across production and development dependencies.
